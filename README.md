# Media.net Self-Serve Campaigns (MVP)

A self-serve retention advertising tool for D2C brands: guided campaign setup, explainable AI budget suggestions, a near real-time Live Monitor, and honest measurement against a holdout group.

Ad delivery runs through a **mock Media.net channel adapter** on a **demo clock** (120× real time by default), so the whole product can be demoed without ad-account credentials.

## Quick start

```bash
npm install
npm run setup     # creates the SQLite DB and seeds a demo brand ("Kaapi & Co.", 2,00,000 synthetic shoppers, 14 campaigns)
npm run dev       # http://localhost:3000
```

Re-run `npm run db:seed` at any time to reset the demo data. The seed refuses to run unless `DATABASE_URL` points at a local SQLite file.

Other commands: `npm test` (Vitest) · `npm run typecheck` · `npm run build`.

## Demo script (5 minutes)

1. **Overview**: 30-day spend, conversions, ROAS, the North Star Metric, and incremental lift vs the 10% holdout. One open alert shows the pixel `begin_checkout` event has stopped firing.
2. **Campaigns → "Win back lapsed buyers"** playbook → wizard. Step 3 shows the **Budget Suggester** with a recommendation, expected range, three plain-language reasons, and the guardrails that bound it. It suggests only; your accept, edit or reject decision is audit-logged.
3. **Launch**, then watch the **Live Monitor** update every 5 s: pacing against the daily budget, spend ceiling, frequency, alerts. During the first 3 days, pausing asks for confirmation (learning period).
4. **Switch role** (top bar) to Editor: you can't raise the spend ceiling, and launches above ₹50,000 go to approval. As Viewer, everything is read-only.
5. **Wallet**: prepaid ledger. If the wallet runs out, every live campaign auto-pauses (hard safety rule) without overshooting.
6. **Audit log**: every launch, pause, budget change, approval and AI decision.

## Deliberate deviations from the target stack (MVP demo)

- **SQLite instead of Postgres** locally, for zero-infra startup. The schema avoids SQLite-only features; to switch, change `provider` in `prisma/schema.prisma` and set `DATABASE_URL`.
- **No Redis/BullMQ yet.** The demo clock advances on each request (`src/lib/sim/runner.ts`) with an optimistic lock so concurrent requests never double-deliver. In production this becomes a worker on a schedule.
- **Demo role switcher instead of auth.** It sets a cookie and acts as the seeded user with that role.
- **shadcn-style components are hand-written** (`src/components/ui.tsx`) rather than generated by the CLI.
